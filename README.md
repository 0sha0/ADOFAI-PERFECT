## 这是什么

一个注入式（DLL）辅助工具，覆盖在 Steam 版《A Dance of Fire and Ice》上运行：

- **实时转谱**：直接读游戏 Mono 运行时的关卡数据（砖块时间 / 转向角 / 长按），
  把**无轨谱面**实时转成 **4K / 5K / 6K / 10K 下坠谱 / 16K（PAD）面板 / CATCH 无轨雨**，
  边玩原版边打另一种玩法；
- **冰与火宏**：宏直接代打**游戏本体**判定线，成绩真实（不是 100% 自动演奏）；
- **辅助读谱 / KeyViewer / 录制 / 皮肤系统 / 配置档案**等一整套工具。

技术栈：纯 C++20 + VS2022 · Dear ImGui 1.92 覆盖层 · Microsoft Detours ·
**静态 CRT（`/MT`）—— 发布版不需要 VC 运行库，也不需要 .NET**，解压即用。

## 界面

v1.3 的界面**完全重写**为 **侧边栏 + 子导航**布局（不再使用顶部页签），

**Etherium Menu 风格**；控件均为自绘（`UiKit.cpp/.h`），不使用原生控件。

### v1.3 更新

**全新界面**

- **侧边栏 + 子导航**布局取代顶部页签：基础功能 / 实时状态 / 辅助读谱 / 一般轨道 / 其他 / 设置 / 关于；
- **半透明面板 + 圆角 + 统一强调色**的 Etherium 风格，控件全部自绘（`UiKit.cpp/.h`）；
- 侧栏左上角品牌区可拖动窗口，右下角可缩放；顶栏实时显示当前页名，子导航紧随其后、不会与标题重叠；
- 页签与页面**严格对齐**，不再出现「点开设置其实是关于」。

**新增模式**

- **16K（PAD）模式页**：Malody Pad 式 4×4 方形面板（非下落式），16 个方块各自独立设键，
  并配**独立的 PAD 写谱引擎**（不是 4K 的复制粘贴）；该模式**只支持内置皮肤**（需求，非降级）。
- **CATCH 模式页**：**无轨**下落雨 + 连续滑动的底部接盘。
  - **鼠标控制接盘**：不绑定键位、没有键位分区；移动鼠标即可左右滑动底部接盘，雨点落线瞬间被盖住即接住（详见下方「CATCH」小节）。
  - 冰火砖 → 连续横向坐标的转换独立成文件（`ChartCatch.cpp`），**与 4K/5K/6K/10K/16K 完全不共用算法**：
    持续同向旋转 = 连续小步推进（渲染成长阶梯，不散落），大回转 = 折返大跳。
  - 内置 **Malody 原皮 Dylamo**（`CatchSkin\`），皮肤同样**独立不互通**。
  - **判定同步本体**：MARVELOUS / PERFECT → 本体 Perfect、GOOD → 本体 Good（并显示快 / 慢）、
    MISS → 本体也 MISS 并断连击；MISS **只显示判定、不会自动重开**，继续游玩即可
    （是否致死看本体判定与「基础功能」页的不死开关）；
  - **多种生成手法**：经典 / 走(Walk) / 冲(Dash) / 超冲(Hyper) / 边冲(Edge) / 阶梯(Stair)。
- **8K 模式页**：`ASDF` + `JKL;` 标准 8 键下坠谱，独立引擎（16 音内外波浪循环 + 楼梯交替 + 最外键重音）。
- **OSU（戳泡泡）模式页**：osu!standard 泡泡玩法，512×384 判定场按 osu! 原版 640×480 game pixel 缩放，
  OD 判定窗（300/100/50/MISS）+ 连击色 / ApproachCircle / 光标拖尾，手法含跳 / 串 / 交互 / 双押 / 技术，固定内置皮肤。- **直播模式（防采集）**：「其他」页独立卡片，可把 IMGUI 界面 / 一般轨道辅助 / 辅助读谱 / 按键反馈
  从推流 / 录像里隐藏，**本机人眼照常可见**；开启后画面左上角带 `ADOFAI-PERFECT` 水印；开关随配置档案保存。

**核心算法**

- **冰与火手法生成重做**：不再把 5K / 6K / 10K 生成成 4K 手型 —— 轮指 / 交互严格按各模式真实手别分工
  （5K = 3+2、6K = 3+3、10K = 5+5、16K = 左二列 / 右二列），并在乐句边界移动手位；
  按 BPM 归一化后按「窗口长度」决定换手 / 不换手 / 回主手，符合大佬实际打冰与火的手法。
- **伪双押优化**（4K / 5K / 6K / 10K / 16K 每模式独立开关）：把冰与火里的「伪双押」按
  **真·同刻双押生成**（同一时刻、两个不同的键），而不是留成一个几毫秒的「突然快轮」。
  判定要求**角度尖锐**且**时间极为接近**（冰火圈对「双押/多押 (Pseudo)」的定义）：
  · 尖锐角：转角 ≤ **30°**（游戏自身 `GetMultipressPenalty` 的「短砖」分界 30.1°，
    覆盖经典 **15° / 30°** 伪双押与 1° 级极小角）；
  · 极为接近：两砖间隔 ≤ **45 ms**（> 22 音/秒，人手没法分成两下）。
  冰火的时间公式 `Δt = 转角/180° × 30/(BPM×speed)`（已对照 `scrMisc.GetTimeBetweenAngles`
  与 `scrLevelMaker` 反编译核对），所以「固定 45 ms 窗口」等价于**角度上限随 BPM 自动伸缩**：
  同一个 30° 在 80 BPM 是 125 ms、120 BPM 是 83 ms（都是普通音，不合并），
  250 BPM 是 40 ms、400 BPM 是 25 ms（都是伪双押，合并）。
  与**快轮 / 轮指**严格区分：只有「单发」的小角步才合并 —— 前一步或后一步本身也是
  小角步时（30°+30°+30°… 的连发）一律保持原样，既不会漏判伪双押，也不会把轮指拆散。
  面板上会实时显示当前 BPM 下等效的角度上限（如 `自适应窗口: 45 ms · ≤ 30° @ 120 BPM`）。
- **长条显示**：按冰与火长条定义重做，长按期间持续显示并按住的反馈，尾端自动换键，避免「松手拍」错位。

**界面与配置**

- **读谱辅助**：中旋改为**蓝色**；位置新增**居中**。
- **改键支持非字母 / 数字键**：空格、`Enter`、`Tab`、方向键、`;` `'` `[` `]` `-` `=` `,` `.` `/` `\` 等都能绑定。

**稳定性**

## 冰与火宏模式

在「其他 → 宏模式」页勾选 **冰与火模式** 后，工具按下面的链条代打：

1. 每帧读取当前砖块判定现场（下一砖、角度误差、`crotchet`、转速、当前状态）；
2. 用与 4K 宏打歌同一套**拟人抖动模型**算出目标毫秒偏移，换算成角度；
3. 在误差到达目标角（含半帧量化补偿）时调用游戏自己的
   `scrPlayer.Hit(isAuto: false)` —— 与玩家出刀同一条判定链：
   `scrPlayer.Hit → scrPlanet.SwitchChosen → scrMisc.GetHitMargin`；
4. 长按砖按游戏 Otto 逻辑在结尾再补一次。

因此**连击 / 准确率 / 失误全部由游戏本体记录**，且**不注入任何系统输入，不动你的鼠标键盘**。

- **抖动模型可调**：目标精准度（90–100%）决定 σ 基准、拟人程度决定比例、
  **抖动幅度（0–100%）是总乘数**——100% = 旧版幅度；三者的组合完全公开透明：
  · 100% 精准 + 0% 拟人 + 0% 幅度 = **绝对零偏移**，每砖命中判定正中心
  （只剩 ±半帧的采样量化），**高 BPM / 紧判定窗也不会断连**；
  · 想要"像真人"就加拟人与幅度——幅度越大高 BPM 越容易掉，可自行权衡。

- **开局无需人工按键**：勾选后会写游戏自己的 `scrController.levelWasSkipped` 标记，
  自动跳过「按任意键开始」的等待（与 debug 的 Beat Level 同源，只跳过等待、不结算关卡）。
- 宏模式与游戏内置自动演奏互斥（开启时抑制 `RDC.auto`）；**不会替你强开不死**：
  正常打歌，拟人失误照原生判定处理（需要不死请到「基础功能」页自行打开）。
- 支持官方 / 自定义 / 额外关卡。

## 下坠谱（4K / 5K / 6K / 10K）

1. 先在游戏里**真正进入关卡**；
2. 到「一般轨道 → 对应模式」页打开「**N K 下坠谱面**」开关（各模式互斥）；
3. 谱面按当前关卡实时生成，**开始打歌后**才下落；判定线在面板下方，显示连击与中央 PERFECT / GOOD / MISS。

> 4K / 5K / 6K / 10K 页**不再重复放「宏打歌」开关**：宏打歌统一在「其他 → 宏模式」页按模式选择。

### 转换风格（每套模式都能选）

| 风格 | 说明 |
|---|---|
| **经典** | 每个模式的原生引擎（连打换手、外键重音、长按条） |
| **叠** | Jack 向：同轨连续重音、短促叠音 |
| **技** | Tech 向：楼梯 / 交叉 / 组合位移 |
| **乱** | Random 向：走向打散，避免规律感 |
| **切** | Trill 向：两键切分、双键交替 |
| **冰火手法** | 按 ADOFAI 键盘手法生成（`AdoGen.h`）：交互 / 轮指 / 混指插指 / 押，长按占手自动拆手；**按模式真实手别分工**，不会退化成 4K |

另有「**伪双押优化**」开关：把冰与火里的 **15° / 30°** 伪双押**生成成真·同刻双押**。
判据是「转角 ≤ 30°」且「两砖间隔 ≤ 45 ms」两条同时成立；冰火里 `Δt = 转角/180° × 30/(BPM×speed)`，
所以固定 45 ms 窗口就等于**角度上限随 BPM 自动伸缩**（面板实时显示等效角度上限），
慢歌里的 30° 普通音不会再被误合并；只合并「单发」小角步，连发小角 = 快轮 / 轮指，一律保持原样。
「**硬抗 BPM**」「**内轮指**」只由冰火手法引擎（`AdoGen.h`）读取，因此**只在「转换风格 = 冰火手法」时出现**。

## 16K（PAD）

- Malody Pad 式 **4×4 方形面板**（**不是**下落式轨道）：16 个方块各自向内收缩，缩到边界时按下方块对应的键；
- 每个方块**可以单独设键**（支持非字母数字键）；
- v2.0 起手法**彻底与轨道模式分家**：不再共用「叠 / 技 / 乱 / 切」，改为**六种经典 16K 写谱手法**
  （jubeat / Malody Pad 社区通用语汇，`Chart16K.cpp` 独立引擎）：

  | 手法 | 写谱语汇 |
  |---|---|
  | **经典** | 邻接移动为主 + 左右手分区平衡 + 高速段强制换手（jubeat 基础写法） |
  | **绕环** | 沿外圈 12 板回旋（回旋图形），回旋方向跟随星球转向；大回转落角落重音 |
  | **阶梯** | 沿行 / 列 / 对角线轨道的单调阶梯，到端点折返、大回转换平行轨道 |
  | **十字** | 沿十字臂（横臂 / 竖臂）行走的图形谱（図形ネタ），臂端折返换平行臂 |
  | **交互** | 双板交替（音押 trill），交互对会周期性换位 |
  | **冰火拆手序** | ADOFAI 专用：星球逐砖交替（火 / 冰）→ **火 = 左两列、冰 = 右两列严格交替**；
  押（同刻多键）按**拆手序**分配：第 1 点给当前手区、第 2 点给另一手区、依此类推，各点落在本手区内 |

- **只使用内置皮肤**：外部 `.msp` 皮肤是按「轨道」写的，套到面板上必然错位，因此该模式不参与外部皮肤选择。

## 8K（ASDF ｜ JKL;）

- 标准 8 键布局：左手 `A S D F`、右手 `J K L ;`（与 osu!mania / Etterna 通行键位一致）；
- 引擎与 4K/5K/6K/10K **完全独立**（`Chart8K.cpp`）：连打走 **16 音内外波浪循环**
  （中心→外侧展开→回中心，每键恰好 2 次、逐音换手），楼梯沿 8 键单方向扫动，
  自然跨过中央 `F→J` 换手，大回转落最外侧 `A` / `;` 作重音；长按占用会自动避让；
- 键位可改（每键槽单独设置），风格同样可选「经典 / 叠 / 技 / 乱 / 切 / 冰火手法」；
- 皮肤与设置独立成页（「一般轨道 → 8K」）。
## CATCH

- **无轨**：没有轨道、没有键位分区、不需要绑定键位；
- **鼠标控制接盘**：移动鼠标，底部接盘平滑跟随；雨点落到判定线的瞬间被接盘盖住就**自动接住**，
  落点越靠接盘中心判定越高（正中 MARVELOUS，靠边 PERFECT / GOOD），没盖住判 MISS；
- **判定同步给冰与火本体**（背景原关由 CATCH **专用打歌引擎**演奏，算法独立于「冰与火宏」）：

  | CATCH 判定 | 冰与火本体 |
  |---|---|
  | MARVELOUS / PERFECT | Perfect |
  | GOOD | Very Early / Very Late（并显示**快 / 慢**） |
  | MISS | Too Early / Too Late（断连击） |

- **MISS 不会自动返回 / 重开**：跟 PERFECT / GOOD 一样照常显示一条判定，打完继续玩；
  是否致死完全交给游戏原关自身判定与你在「基础功能」页打开的**不死开关**；
- **打歌精准度** 0–100%（设置页）：越低，CATCH 的偏差越少带进本体（越容易吃 Perfect）；
- **多种生成手法**（设置页「手法」，取自 osu!catch 的移动语汇）：

  | 手法 | 说明 |
  |---|---|
  | **经典** | 跟随冰火旋转角：持续同向旋转 → 连续**长阶梯**，大回转 → 折返大跳 |
  | **走 Walk** | 相邻吸附区之间的小步走位，几乎不需要跨区 |
  | **冲 Dash** | 保持「冲刺距离」，每 1~2 音换向，接盘要来回跨区 |
  | **超冲 Hyper** | 大跨度滑行，同向连走 2~4 音再回摆（半屏扫描） |
  | **边冲 Edge** | 落点贴左右边缘来回拉满（edge dash / pixel dash 的极限接法） |
  | **阶梯 Stair** | 单调同向小步，只在边界折返 |

- 冰火长条 → 竖直长条（不散落）；
- 皮肤固定为内置 **Malody 原皮 Dylamo**（`CatchSkin\`），**不与轨道模式互通**；
- 含自动打歌 / 宏打歌（在「其他 → 宏模式」页选择 CATCH）。

### 改键

点某个键槽后按新键，**必须点「确认」才真正生效**；「取消」原样回退，「恢复默认」回到该模式默认键位。

## OSU（戳泡泡）

把冰与火的无轨谱面实时铺成 osu!standard 的打击点，玩法与 PC 版 osu! 一致：

- **判定场**：512×384 game pixel，按 osu! 原版规则缩放 —— 1 game pixel = 640×480 窗口下的 1 屏幕像素，
  高分辨率下视觉大小不变，判定场水平居中、比窗口中心低 8 game pixel（osu! wiki: Playfield）；
- **泡泡**：连击色填充的 HitCircle（连击色取 osu! 默认皮肤四色 `#FFC000 / #00CA00 / #127CFF / #F21839`）、
  中央连击编号、由外向内收缩的 **ApproachCircle**（AR5 = 1200 ms 提前量，4×→1× 半径）；
- **操作**：鼠标瞄准 + **左键 / 右键 或 `Z` / `X`** 点击；点到泡泡时按落点距离判定，
  空点无惩罚（与 osu! 相同）；
- **判定窗**（osu! 官方公式，设置页可调 OD）：

  | 判定 | 判定窗 |
  |---|---|
  | 300 | `80 - 6 × OD` ms |
  | 100 | `140 - 8 × OD` ms |
  | 50  | `200 - 10 × OD` ms |
  | MISS | 超出 50 的判定窗（不点也会 MISS） |

- **同步回冰与火本体**：300 / 100 → 本体 Perfect、50 → 本体 Good（并显示快 / 慢）、MISS → 本体 MISS 并断连击；
  MISS 只显示判定、**不会自动重开**（是否致死看本体判定与「基础功能」的不死开关）；
- **手法**（设置页「手法」，取自 osu! wiki 的 Gameplay/Pattern：Jump / Stream）：

  | 手法 | 说明 |
  |---|---|
  | **经典** | 跟随冰火旋转角：快而小的音（1/4 拍）走 Stream，大回转走 Jump |
  | **跳 Jump** | 1/2 拍式大间距单点，甩动手腕 |
  | **串 Stream** | 1/4 拍式密集同向小间距，指交替连打 |
  | **交互 Alt** | 跳 / 串逐音交替 |
  | **双押 Doubles** | 成对叠放的「点两下同一个位置」式 |
  | **技术 Tech** | 间距随转角抖动、更贴角度的手法 |

- **皮肤**：固定使用**内置 osu! 皮肤**（程序化绘制，不读取外部 `.msp` / 皮肤目录）。
## 录制

- **开始 / 暂停 / 继续**：暂停 = 收尾当前 MP4（写 moov），继续 = 新开一段文件；
- **输出目录**：可直接编辑 / **浏览…**（系统「选择文件夹」对话框，可先进入任意目录预览再选定）/
  应用 / 一键打开；目录写进 `adofai_perfect.cfg`，也随**配置档案**一起保存与加载；
- **帧率 15–144、码率 2–100 Mbps**：Media Foundation H.264 硬件编码，编码队列满时丢帧而不卡游戏；
- **系统声音**：WASAPI 回环采集默认播放端点 → AAC-LC 48 kHz 立体声，与画面共用同一 QPC 时间基准（音画同步）；
- **实时统计**：写入帧数 / 总帧数 / 是否掉帧 / 当前文件名；
- **录不上会直接告诉你原因**：输出目录无效、编码器不可用、磁盘写失败时，统计行下方会显示
  `REC FAILED: …`，不会一直停在 `0/N`；窗口尺寸是奇数时自动裁成偶数（H.264 要求），
  同一秒内重开新分段也不会撞文件名；
- 也可在 4K/5K/6K/10K 页打开「录制」开关，或在录制页勾选「自动」跟随打歌自动开始；
- 录制相关设置（目录 / 帧率 / 码率 / 自动）都会随**配置档案**一起保存与加载。

## 直播模式（防采集）

在「**其他**」入口页的**直播模式**卡片里打开总开关，再勾选要"藏起来"的元素
（IMGUI 菜单界面 / 一般轨道辅助 / 辅助读谱 / 按键反馈）。

- **人眼照常可见，只有采集端看不到**：被勾选的元素会被画到一块独立的**防采集覆盖窗口**上
  （置顶 / 鼠标穿透 / 每像素透明），并对该窗口调用
  `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` —— 于是窗口捕获 / 游戏捕获 / 显示器捕获
  都拍不到它，而你在显示器上看得一清二楚；游戏画面本身不再包含这些元素，抓到的就是干净画面。
- **水印**：开启后游戏画面**左上角**会出现 **ADOFAI-PERFECT** 水印（水印属于"给观众看的"，
  推流里能看到）。
- **不会把人眼也藏掉**（安全网）：独占全屏时覆盖层不可能盖在游戏上，此时**直接不隐藏**；
  覆盖层最近没有真正上屏（DComp 合成失败 / 设备丢失 / Present 失败）时同样**不隐藏** ——
  宁可直播里能看到，也绝不让你自己看不见。状态行会显示 `off / dcomp / layered / unavailable`。
- 支持 **OBS / 哔哩哔哩直播姬 / 各类录屏软件**；对**显示器 / 游戏 / 窗口采集**都有效。
- 开关与勾选项都会**持久化**：写进 `adofai_perfect.cfg`，也随**配置档案**一起保存 / 加载。

```
bin/Release/Injector.exe        注入器
bin/Release/ADOFAIPerfect.dll   覆盖层模块（内嵌 LOGO 资源）
```

Release 使用**静态 CRT**（`/MT`），产物不依赖 `vcruntime140.dll` / `msvcp140.dll`。

> 本地跑起来直接用 `bin\Release\Injector.exe` 就行：内置皮肤在仓库根目录的 `KSkin\` / `CatchSkin\`，
> 解析时会自动从 `bin\Release\` 向上找到它们；用 Release 里的 zip 则皮肤已经和 exe 放在一起。

> ⚠️ **不要用「重新生成（Rebuild）」**：MSBuild 的 Clean 会清空 `bin\Release\`，
> 把 `Injector.exe`、`adofai_perfect.cfg`、导入的皮肤一起删掉。请用「生成（Build）」；
> 需要全量重编时先备份运行目录（`obj\` 可随时删，只影响编译缓存）。

## FAQ

**Q：提示缺少 `vcruntime140.dll` / `msvcp140.dll`？**
A：Release 为静态 CRT，不存在该依赖。若仍报错，说明用的是自行构建的 Debug 产物，请换 Release。

**Q：进关卡后不显示转谱谱面？**
A：先确认 `KSkin\` / `CatchSkin\` 还在（是不是被误删或被「重新生成」清掉了）；
再真正进入关卡后打开开关。日志 `%LOCALAPPDATA%\ADOFvec\adofai_perfect.log` 里会有
`[skin] builtin dir = ...`、`[skin] ready: ...` 与逐条转谱诊断（砖数、长按数、时长、Lv、风格）。

**Q：CATCH 怎么操作？要按哪个键？**
A：**不用按键，用鼠标**。左右移动鼠标，底部接盘平滑跟随；雨点落到判定线时被接盘盖住就接住（正中 MARVELOUS、靠边 PERFECT / GOOD），没盖住判 MISS。MISS 只显示判定、**不会自动重开**，继续游玩即可（是否致死看游戏本体与「基础功能」页的不死开关）；想自动打歌在「其他 → 宏模式」页选 CATCH。

**Q：CATCH 皮肤能换成别的吗？**
A：不能。CATCH 与 16K(PAD) 都固定使用各自的内置皮肤；4K/5K/6K/10K 才可以在皮肤页选外部 `.msp`。

**Q：音画不同步 / 判定总觉得早或晚？**
A：用对应模式页的「延迟」滑杆微调，或打开「自动调整延迟」按歌曲动态校准；判定宽度可选宽 / 中 / 严。

**Q：冰与火宏不代打？**
A：确认「其他 → 宏模式」页勾选了冰与火模式，并已真正进入关卡；日志里会出现
`[Detour] fire macro hooked`、`[Detour] ctrl Update hooked` 与 `[fire] hit floor=... ok=1`。

**Q：找不到「宏打歌」开关了？**
A：4K / 5K / 6K / 10K / 16K / CATCH 的宏打歌统一收纳在「其他 → 宏模式」页，先在那里选中模式。

**Q：页面文字被挡住 / 控件重叠？**
A：内容区随窗口宽度自适应并可上下滚动，把窗口拖宽即可完整显示。

**Q：打开「关于」页会弹浏览器？**
A：不会。关于页只提供「演示视频 / GitHub / 配置目录」三个按钮，需要手动点击才会打开。

**Q：注入被拦截？**
A：注入器需要 `CreateRemoteThread` 权限，被杀软 / Defender 拦截时请放行。
